# Changelog

## 1.0.0 - 2026-09-20

First commit. Implements the collection requested in [RustHound-CE#69](https://github.com/g0h4n/RustHound-CE/issues/69). Local group enumeration over MS-SAMR: for each target, `SamrConnect2` then `SamrOpenDomain` on the BUILTIN domain `S-1-5-32`, then one `SamrOpenAlias` plus `SamrGetMembersInAlias` per selected RID (544 Administrators, 555 Remote Desktop Users, 562 Distributed COM Users, 580 Remote Management Users), producing the BloodHound `AdminTo`, `CanRDP`, `ExecuteDCOM` and `CanPSRemote` edges. `-c` selects `All` (default), `AdminOnly`, `RdpOnly`, `DcomOnly` or `PSRemoteOnly`. Read-only throughout: the alias handle is opened with `ALIAS_LIST_MEMBERS` and no write opnum is compiled in.

Opnums 27 and 33 are implemented in `src/samr_alias.rs` rather than upstream, because `dcerpc` 0.2.11 ships only the SAMR *user* path (`Connect2`, `EnumerateDomains`, `LookupDomain`, `OpenDomain`, `EnumerateUsersInDomain`). No fork is needed: the crate's transport is public (`SmbPipe::{new,bind,call}`, `samr_syntax()`, `SamrHandle`, the `encode_*`/`decode_*` helpers) and the NDR layer is the published `ms-ndr` crate re-exported as `dcerpc::ndr`. The one friction point is that `samr::{encode_sid, decode_sid}` are private upstream, so RPC_SID marshaling is reimplemented here; a three-line PR making those `pub` would delete that block. Requires `dcerpc` 0.2.11+.

Members that live in the target's own SAM are dropped by default: they have no node in BloodHound, so emitting them would create a dangling edge. The machine SID used for that test is learned from SAMR itself (`SamrEnumerateDomains` then `SamrLookupDomainInSamServer` on the non-BUILTIN domain), which avoids both an LDAP round trip and an LSA `LsarQueryInformationPolicy` call that `dcerpc` does not expose. The prefix test compares sub-authority arrays rather than rendered strings, so `S-1-5-21-1-2-30-500` is not mistaken for a child of `S-1-5-21-1-2-3`. `--include-local` keeps them. The filter is disabled automatically on a domain controller, where SAMR's non-BUILTIN domain is the AD domain itself and its SID is the domain SID: filtering on it would drop every domain principal and return a nearly empty Administrators group on the highest-value target. DC-ness is judged from the domain name SAMR reports, since the domain SID is unknown without LDAP, and the result is surfaced as `is_domain_controller` in the JSON.

Authentication mirrors RustHound-CE: NTLMv2 bind (`-p`), pass-the-hash (`-H`, accepting `NTHASH`, `:NTHASH` and `LMHASH:NTHASH`), and Kerberos pass-the-ticket (`-k`, TGT read from `KRB5CCNAME`, `--kdc` to pin a DC). `src/transport/{smb,gss,kerberos}.rs` are copied unchanged from RustHound-CE's own `src/transport/` so the two trees cannot drift; `ldap.rs` and `cert.rs` are absent since this tool speaks neither. Kerberos material is rebuilt per host because the AP-REQ targets that host's `cifs/<host>` SPN, so Kerberos targets must be FQDNs. `AuthConfig` implements `Debug` by hand to redact the password and hash.

`computers[].LocalGroups[]` is serialized in the exact shape of RustHound-CE's `objects::common::LocalGroup` (`ObjectIdentifier`, `Results`, `LocalNames`, `Collected`, `FailureReason`), so the port is a field map rather than a rewrite. `LocalNames` stays empty until `dcerpc` grows LSAT `LsarLookupSids`; it currently exposes `LsarLookupNames`, which resolves the other direction. `ObjectType` is guessed from the SID and comes back as `Base` for domain principals, which RustHound-CE resolves against the graph at merge time.

`ACCESS_DENIED` is never fatal: the alias is emitted with `"Collected": false` and a `FailureReason`, and the scan continues. Offline tests cover the NDR round trip, the empty alias, `STATUS_ACCESS_DENIED`, the SID prefix trap, and a hostile reply claiming `Count = u32::MAX` on a truncated stub.
